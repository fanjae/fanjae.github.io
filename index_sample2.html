01

패킷 경계와 이벤트 순서를 보장하는 온라인 게임 서버 설계

TwoFacedPoker는 C++ 서버와 C# 클라이언트로 구현한 2인용 온라인 카드 게임입니다. 서버가 방·턴·베팅·승패 상태를 관리하고, 클라이언트와 일관된 게임 흐름을 유지하는 것을 목표로 개발했습니다. 초기에는 클라이언트가 보낸 데이터를 recv() 한 번으로 수신한 뒤 반환된 버퍼를 하나의 명령어로 간주했습니다.

테스트 중 베팅과 턴 이벤트가 간헐적으로 잘못 처리되는 문제가 발생했습니다. 원인을 추적하며 TCP는 바이트 스트림 기반이므로 하나의 호출이 하나의 메시지를 보장하지 않고, 메시지 경계를 애플리케이션에서 직접 처리해야 한다는 점을 확인했습니다.

이후 패킷 앞에 4바이트 길이 헤더를 추가하고, 정해진 크기만큼 모두 수신·전송하는 RecvAll()과 SendAll()을 서버와 클라이언트에 동일하게 적용했습니다. 또한 연결별 송신 큐와 Sender Thread를 도입해 여러 Worker Thread가 동일한 소켓에 직접 송신하지 않도록 했습니다. condition_variable로 busy waiting을 방지하고, 연결 종료 시 방과 게임 상태를 정리한 뒤 shutdown() → notify_all() → join() → closesocket() 순서로 자원을 정리했습니다.

이 경험을 통해 네트워크 라이브러리가 보장하는 범위와 애플리케이션이 직접 책임져야 하는 부분을 구분하는 법을 배웠으며, 동작하는 코드에서 나아가 통신의 신뢰성과 연결 수명까지 고려하는 서버를 설계하게 되었습니다.

02

게임 상태의 일관성을 보장하는 저장 시스템 설계

처음에는 빠른 구현을 위해 저장 로직을 SaveManager 한 곳에서 관리했습니다. 저장 대상이 영웅, 장비, 인벤토리, 퀘스트 등으로 늘어나면서 SaveManager가 모든 시스템의 구조를 알아야 했고, 새로운 기능을 추가할 때마다 중앙 저장 로직을 수정해야 했습니다.

이를 개선하기 위해 ISaveDataWriter 인터페이스를 도입했습니다. 각 시스템이 자신의 런타임 상태를 GameSaveData에 반영하도록 책임을 분리하고, SaveManager는 등록된 Writer를 순회하며 WriteSaveData()를 호출하는 역할만 담당하도록 구조를 개선했습니다.

이후 GameSaveDataSnapshot을 생성하고 JSON 직렬화와 파일 입출력을 백그라운드에서 처리했습니다. 최상위 객체뿐 아니라 내부의 리스트와 Dictionary까지 새 객체로 복사해 저장 시점의 독립적인 사본을 만들었고, 저장 중 새로운 요청이 들어오면 요청을 합쳐 현재 저장이 끝난 뒤 최신 상태를 다시 저장하도록 구현했습니다.

이 경험을 통해 저장 시스템은 단순한 파일 입출력 기능이 아니라 플레이어의 진행 데이터를 안전하게 보존하는 핵심 시스템이라는 점을 배웠습니다. 앞으로도 기능 구현에 그치지 않고 시스템의 확장성과 데이터 일관성을 함께 고려하겠습니다.

강점 / 조율과 책임

팀원의 자율성을 존중하면서도 전체 진행 상황을 파악하고 필요한 순간에 조율합니다. IDLEAdventure 개발 당시 데일리 스크럼으로 진행 상황을 확인하고, 작업이 겹칠 가능성이 있는 부분은 미리 공유했습니다. 일정이 지연될 때는 업무를 재분배하고 씬 연결과 시스템 통합을 직접 맡아 팀원이 핵심 기능에 집중할 수 있도록 했습니다.

보완 중인 점 / 기술 부채 관리

일정이 임박하면 팀의 목표를 맞추기 위해 업무 범위를 넓히는 경향이 있습니다. 최종 빌드 전에는 우선순위가 높은 기능에 집중하며 저장 구조 개선이나 개인 코드 최적화를 후순위로 미루기도 했습니다. 현재는 구현 전에 필수 기능과 개선 작업을 구분하고, 위험 요소와 리팩토링 일정을 미리 계획하려고 노력합니다.

플레이어의 행동이 오류 없이 결과로 이어지도록

입사 초기에는 프로젝트의 코드 구조와 게임 플레이 흐름, 데이터가 클라이언트와 서버 사이에서 전달되는 과정을 빠르게 파악하겠습니다. 기존 팀의 코딩 규칙과 개발 프로세스를 준수하며 작은 기능 수정과 버그 재현·해결부터 정확하게 수행해 프로젝트에 안정적으로 적응하겠습니다.

이후에는 팀의 우선순위에 따라 클라이언트, 서버, 시스템 통합 등 필요한 업무를 맡아 기능의 시작부터 실제 게임 반영까지 책임지겠습니다. 데이터 흐름과 시스템 간 의존성, 예외 상황을 함께 검토해 변경에 강한 구조를 만들겠습니다.

장기적으로는 특정 영역에만 한정되지 않고 프로젝트의 핵심 시스템을 독립적으로 설계하고 개선할 수 있는 프로그래머로 성장하겠습니다. 해결한 문제와 설계 의도를 팀과 공유해 개인의 구현을 넘어 팀 전체가 유지보수하기 쉬운 구조를 만드는 데 기여하겠습니다.
