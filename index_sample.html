01

패킷 경계와 이벤트 순서를 보장하는 온라인 게임 서버 설계

TwoFacedPoker는 C++ 서버와 C# 클라이언트로 구현한 2인용 온라인 카드 게임입니다. 서버가 방·턴·베팅·승패 상태를 관리하고, 클라이언트와 일관된 게임 흐름을 유지하는 것을 목표로 개발했습니다.

초기에는 클라이언트가 보낸 데이터를 recv() 한 번으로 수신한 뒤 반환된 버퍼를 하나의 명령어로 간주했습니다. 테스트 중 베팅과 턴 이벤트가 간헐적으로 잘못 처리되었고, TCP가 하나의 호출에서 하나의 메시지를 보장하지 않는다는 점을 원인으로 추적했습니다.

이후 패킷 앞에 4바이트 길이 헤더를 추가하고, 헤더와 본문을 정해진 크기만큼 모두 수신·전송하는 RecvAll()과 SendAll()을 구현해 서버와 클라이언트에 동일하게 적용했습니다. 반복 테스트와 패킷 로그 확인을 통해 기존 파싱 실패가 테스트 범위 내에서 재현되지 않음을 확인했습니다.

또한 여러 Worker Thread가 동일한 소켓에 직접 송신하지 않도록 연결별 송신 큐와 Sender Thread를 도입했습니다. condition_variable로 busy waiting을 방지하고, 연결 종료 시 방·게임 상태 정리 후 shutdown() → notify_all() → join() → closesocket() 순서로 자원을 정리했습니다.

02

게임 상태의 일관성을 보장하는 저장 시스템 설계

처음에는 빠른 구현을 위해 저장 로직을 SaveManager 한 곳에서 관리했습니다. 저장 대상이 늘어나면서 SaveManager가 모든 시스템의 구조를 알아야 했고, 새로운 기능마다 중앙 로직을 수정해야 했습니다.

이를 개선하기 위해 ISaveDataWriter 인터페이스를 도입했습니다. 각 시스템이 자신의 런타임 상태를 GameSaveData에 반영하고, SaveManager는 등록된 Writer를 순회하며 WriteSaveData()를 호출하는 역할만 담당하도록 분리했습니다.

GameSaveDataSnapshot을 생성한 뒤 JSON 직렬화와 파일 입출력을 백그라운드에서 처리했습니다. 최상위 객체뿐 아니라 리스트와 Dictionary까지 새 객체로 복사해 저장 시점의 독립적인 사본을 만들고, 저장 중 새로운 요청은 합쳐서 최신 상태를 다시 저장하도록 구성했습니다.

이 경험을 통해 저장 시스템은 단순한 파일 입출력이 아니라 플레이어의 진행 데이터를 안전하게 보존하는 핵심 시스템이라는 점을 배웠습니다. 기능 구현과 함께 확장성·데이터 일관성을 고려하는 개발자가 되겠습니다.
