Project Overview

게임의 상태와 제작 흐름을 연결하다

  • 주요 담당저장·로드 · 장비·인벤토리 · 레벨 공명
  • 제작 지원Unity Editor Tool · 콘텐츠 검수 자동화
  • 협업데일리 스크럼 · Git 브랜치 병합 · 시스템 통합
  • 핵심 관점데이터 정합성 · 상태 관리 · 반복 비용 감소

담당 기능 및 주요 구현·설계

게임의 상태를 안전하게 저장하고, 콘텐츠 제작과 시스템 연동의 반복 비용을 줄이는 구조를 설계했습니다.

01 / SAVE SYSTEM

통합 저장 시스템 설계와 비동기 저장 정합성 확보

문제

개별 저장 처리에서는 최신 데이터가 덮어써지거나 종료 시점의 데이터가 유실될 가능성이 있었습니다.

설계

SaveManager 중심의 통합 저장 구조를 적용하고, 저장 시점의 상태를 Snapshot으로 분리해 백그라운드에서 직렬화하도록 구성했습니다.

정합성

연속 요청과 생명주기 전환 상황을 고려해 저장 요청을 합치고, 최신 상태를 기준으로 다시 저장하도록 처리했습니다.

결과

게임 진행 중 원본 데이터가 변경되어도 저장 중인 사본에 영향을 주지 않도록 하여 저장 데이터의 일관성을 확보했습니다.

상세 설계 보기

WriteSaveData()로 각 시스템의 런타임 상태를 통합 저장 데이터에 반영한 뒤, 저장 시점의 독립적인 Snapshot을 생성했습니다.

  • 최상위 객체뿐 아니라 내부 리스트와 Dictionary까지 복사해 원본과 저장 데이터를 분리
  • 백그라운드 직렬화 중 게임 상태가 변경되어도 저장 중인 사본이 영향을 받지 않도록 처리
  • 저장 중 새 요청이 들어오면 요청을 합치고 현재 저장 완료 후 최신 상태를 다시 저장

02 / EQUIPMENT & INVENTORY

InstanceId 기반 장비·인벤토리 시스템

문제

동일 종류의 장비를 여러 개 보유할 때 ItemId만으로는 개별 장비의 상태를 식별하기 어려웠습니다.

설계

EquipmentSO와 OwnedEquipmentData를 분리하고, InstanceId 기반으로 개별 장비를 관리했습니다.

구조

Inventory·ClassEquipmentSet·ClassEquipmentService로 보유·장착·검증 책임을 나누었습니다.

자동화

자동 장착과 세트 능력치 계산을 구현하고, EquipmentCsvImporter로 144종 장비 데이터의 생성·검증·등록을 자동화했습니다.

상세 설계 보기

정적인 장비 정의와 플레이어가 실제로 보유한 장비 상태를 분리해, 동일한 종류의 장비도 개별 상태를 유지할 수 있도록 설계했습니다.

  • EquipmentSO는 공통 정의를, OwnedEquipmentData는 강화·장착 등 런타임 상태를 담당
  • InstanceId를 기준으로 보유·장착·저장·복원 과정의 참조 무결성 검증
  • CSV Importer로 144종 장비 데이터의 생성·검증·등록 과정을 자동화

03 / UNITY EDITOR TOOL

콘텐츠 제작과 검수를 위한 Editor Tool

문제

VFX·SFX를 검수할 때마다 게임을 실행하거나 씬을 구성해야 해 반복적인 제작·확인 비용이 발생했습니다.

VFX

PreviewRenderUtility 기반의 독립 렌더링 환경을 구성해 에디터 내부에서 이펙트를 확인할 수 있도록 했습니다.

SFX

AssetDatabase 검색·캐시와 AudioUtil 호환 처리를 적용해 사운드 프리뷰 기능을 구현했습니다.

결과

캐릭터 기준점 비교, 재생 제어, 폴더 필터, 볼륨·피치·반복 재생을 제공해 콘텐츠 검수 과정을 에디터 내부로 단축했습니다.

상세 기능 보기
  • VFX 프리뷰: 독립 렌더링 환경에서 캐릭터 기준점과 이펙트 위치 비교
  • SFX 프리뷰: 폴더 필터, Asset 검색·캐시, 볼륨·피치 조절과 반복 재생
  • 콘텐츠 제작자가 게임을 실행하지 않고도 에디터에서 결과를 확인하도록 검수 흐름 단축

TROUBLESHOOTING

전투 진입 경로별 플레이어 위치 저장 누락

전투 진입 경로에 따라 플레이어 위치가 저장되지 않는 문제를 확인하고, 저장 호출 시점과 전투 진입 흐름을 점검해 저장·복원 과정에 반영했습니다.

프로젝트에서 얻은 경험

게임 시스템은 개별 기능의 동작만으로 완성되지 않습니다. 저장 시점의 데이터 정합성, 장비 상태의 식별과 참조, 콘텐츠 제작 과정의 반복 비용, 팀원 기능과의 통합까지 함께 고려해야 플레이어 경험을 안정적으로 연결할 수 있다는 점을 배웠습니다.
